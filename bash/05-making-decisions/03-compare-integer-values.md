# Bash：先验证十进制整数，再进行算术比较

#!/usr/bin/env bash

[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]] || exit 2

## 为什么必须先验证输入

Bash 的：

```bash
(( ... ))
```

会把内容当作**算术表达式**，而不是普通字符串。

例如：

```bash
(( 40+40 >= 80 ))
```

其中 `40+40` 会先被计算成 `80`。因此，不能直接把用户输入交给算术上下文。

正确流程是：

```text
用户输入
   ↓
正则验证是否为合法十进制整数
   ↓
保存到变量
   ↓
使用 (( ... )) 进行数值比较
```

## 输入验证

脚本使用：

```bash
[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]] || exit 2
```

正则表达式：

```regex
^(0|[1-9][0-9]*)$
```

只允许：

```text
0
1
9
10
79
80
100
12345
```

拒绝：

```text
40+40
-5
eighty
0100
049
```

### 为什么拒绝前导零

在 Bash 算术环境中，带前导零的整数通常会被解释为八进制。

例如：

```bash
(( 0100 ))
```

实际上表示：

```text
64
```

而不是十进制 `100`。

因此：

```bash
^(0|[1-9][0-9]*)$
```

要求：

* `0` 可以单独存在；
* 非零整数必须以 `1-9` 开头；
* 后面可以跟任意数量的数字。

这样可以在进入算术环境之前消除八进制解释的问题。

## `=~` 右侧不要加引号

正确：

```bash
[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]]
```

错误：

```bash
[[ "$1" =~ "^(0|[1-9][0-9]*)$" ]]
```

在 `[[ ... =~ ... ]]` 中，右侧需要作为正则表达式解释；加引号会使被引用部分按字面文本匹配。

左侧变量则可以正常加引号：

```bash
"$1"
```

## 算术比较

验证成功后：

```bash
score=$1
```

然后：

```bash
(( score >= 80 ))
```

在 `(( ... ))` 内部，变量名可以直接写：

```bash
score
```

不需要：

```bash
$score
```

`>=` 是数值比较，因此：

```text
79  → false
80  → true
100 → true
```

80 本身也满足条件，因为使用的是：

```bash
>=
```

而不是：

```bash
>
```

## 非法输入行为验证

脚本已经验证以下输入：

```text
40+40
0100
-5

空字符串
```

它们全部：

```text

```

因此不会让未验证的文本进入 Bash 的算术求值环境。
