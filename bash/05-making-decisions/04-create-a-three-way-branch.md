# Bash 数值输入校验与 `if / elif / else` 分支判断

## 一、为什么不能直接把用户输入交给 `(( ... ))`

Bash 的算术表达式：

```bash
(( ... ))
```

并不会严格要求参与计算的内容必须是十进制数字。

例如：

```bash
score=high

if (( score < 50 )); then
    echo low
fi
```

这里看起来像是在比较字符串 `high` 和数字 `50`，但 Bash 并不是这样处理的。

### 1. 单词可能被当成变量名

在算术上下文中：

```bash
(( score < 50 ))
```

Bash 会读取变量 `score` 的值。假设：

```bash
score=high
```

那么 `high` 又会被当成一个算术变量名。

如果变量 `high` 没有定义，它通常会被当作 `0`：

```text
high → 未定义变量 → 0
```

于是：

```bash
(( score < 50 ))
```

实际可能变成：

```bash
(( 0 < 50 ))
```

结果为真，因此程序错误地把无效输入 `high` 分类成：

```text
low
```

这说明：

> **不能使用算术比较本身来验证用户输入是不是数字。**

必须先验证输入格式，再进行算术运算。

---

## 二、前导零会触发八进制问题

Bash 的整数算术支持不同进制。

例如：

```bash
010
```

以 `0` 开头的整数可能按照八进制（octal）解释：

```text
010（八进制） = 8（十进制）
```

因此：

```bash
049
```

会出现问题，因为八进制只允许：

```text
0 1 2 3 4 5 6 7
```

而不能包含：

```text
8 9
```

所以类似：

```bash
(( 049 < 50 ))
```

并不是普通的十进制 `49 < 50`，而可能直接产生算术错误。

因此，仅验证“字符串全部由数字构成”还不够。

例如这个正则：

```bash
^[0-9]+$
```

会接受：

```text
049
```

但 `049` 并不是这里希望接受的规范十进制输入。

---

## 三、使用正则表达式验证规范十进制整数

可以使用：

```bash
[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]]
```

完整的 guard（输入保护）可以写成：

```bash
[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]] || exit 2
```

它的作用是：

> 只有参数是规范的非负十进制整数时才继续执行，否则立即以状态码 `2` 退出。

---

## 四、正则表达式逐部分解释

```regex
^(0|[1-9][0-9]*)$
```

可以拆成：

```text
^
(
    0
    |
    [1-9][0-9]*
)
$
```

### `^`

表示字符串开头。

### `$`

表示字符串结尾。

两者配合意味着：

> 整个参数必须完全符合正则，而不是只要求其中某一部分符合。

---

### `0`

单独允许数字：

```text
0
```

---

### `|`

表示“或者”。

所以：

```regex
0|[1-9][0-9]*
```

表示：

```text
要么是 0
要么是一个不以 0 开头的正整数
```

---

### `[1-9]`

第一位必须是：

```text
1 到 9
```

因此不能以 `0` 开头。

---

### `[0-9]*`

后面允许出现零个或多个数字。

例如：

```text
5
49
123
9000
```

都可以匹配。

---

## 五、哪些输入会通过验证

| 输入      | 是否通过 | 原因            |
| ------- | ---: | ------------- |
| `0`     |    ✅ | 明确允许          |
| `1`     |    ✅ | 第一位为 1–9      |
| `49`    |    ✅ | 合法十进制整数       |
| `80`    |    ✅ | 合法十进制整数       |
| `12345` |    ✅ | 合法十进制整数       |
| `049`   |    ❌ | 不允许前导零        |
| `00`    |    ❌ | 不允许多位数字以 0 开头 |
| `high`  |    ❌ | 包含字母          |
| `40+40` |    ❌ | 包含运算符         |
| `-5`    |    ❌ | 不允许负号         |
| `5.0`   |    ❌ | 不允许小数点        |
| 空字符串    |    ❌ | 不符合任何分支       |

因此：

```bash
[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]] || exit 2
```

不仅阻止了 `high`，也阻止了：

```text
049
40+40
-5
```

等不符合预期的输入进入 Bash 算术环境。

---

## 六、为什么正则右边不要加引号

正确：

```bash
[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]]
```

不要写成：

```bash
[[ "$1" =~ "^(0|[1-9][0-9]*)$" ]]
```

在：

```bash
[[ ... =~ ... ]]
```

中，右边应该作为正则表达式使用。

将整个右侧模式加引号可能改变 Bash 对它的解释方式，使其不能按照预期执行正则匹配。

可以记住：

```bash
[[ "$value" =~ 正则 ]]
```

通常：

* 左边变量加引号；
* 右边正则保持不加引号。

# Bash `if / elif / else` 的范围判断

## 一、基本结构

Bash 的条件分支可以写成：

```bash
if (( score < 50 )); then
    ...
elif (( score < 80 )); then
    ...
else
    ...
fi
```

执行过程是：

1. 检查第一个条件；
2. 如果为真，执行对应代码并跳过后面的分支；
3. 如果为假，再检查 `elif`；
4. 如果所有条件都不成立，执行 `else`。

因此：

> **只执行第一个满足条件的分支。**

---

## 二、为什么第二个条件不需要写下界

假设代码为：

```bash
if (( score < 50 )); then
    echo low
elif (( score < 80 )); then
    echo medium
else
    echo high
fi
```

### 第一种情况：`score < 50`

例如：

```text
49
```

第一个判断成立：

```bash
(( 49 < 50 ))
```

于是输出：

```text
low
```

后面的 `elif` 不再执行。

---

### 第二种情况：进入 `elif`

如果程序已经进入：

```bash
elif (( score < 80 ))
```

就意味着前面的：

```bash
(( score < 50 ))
```

已经失败。

也就是说，此时已经知道：

```text
score >= 50
```

因此 `elif` 只需要检查：

```bash
score < 80
```

两条信息结合：

```text
score >= 50
score < 80
```

得到：

```text
50 <= score < 80
```

即：

```text
50～79
```

所以没有必要写成：

```bash
elif (( score >= 50 && score < 80 )); then
```

虽然这样也能工作，但条件重复了已经由控制流保证的信息。

更简洁的写法是：

```bash
elif (( score < 80 )); then
```

---

## 三、三个分支实际代表的范围

下面的代码：

```bash
if (( score < 50 )); then
    echo low
elif (( score < 80 )); then
    echo medium
else
    echo high
fi
```

实际等价于：

| 分支                 | 范围       | 输出       |
| ------------------ | -------- | -------- |
| `score < 50`       | `0～49`   | `low`    |
| 前面失败且 `score < 80` | `50～79`  | `medium` |
| 前两个都失败             | `80` 及以上 | `high`   |

边界值尤其重要：

```text
49 → low
50 → medium
79 → medium
80 → high
```

这也是检查条件边界是否正确的典型方法。

# Shell 命令退出状态

Shell 命令执行结束后都会产生一个退出状态（exit status）。

通常：

```text
0      表示成功
非 0   表示失败或特殊情况
```

例如：

```bash
exit 2
```

表示脚本立即结束，并把状态码 `2` 返回给调用者。

可以使用：

```bash
echo $?
```

查看上一条命令的退出状态。

例如：

```bash
./classify.sh high
echo $?
```

如果脚本正确拒绝输入：

```text
2
```

---

## 无效输入为什么应该不打印任何内容

如果要求：

```text
high → 无输出，退出状态 2
```

输入检查就应该放在所有 `echo` 之前：

```bash
[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]] || exit 2
```

如果验证失败，程序立刻退出，因此不会进入任何分类分支，也不会产生标准输出。

---

# 完整示例：安全地分类一个十进制整数

```bash
#!/usr/bin/env bash

[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]] || exit 2

score=$1

if (( score < 50 )); then
    echo low
elif (( score < 80 )); then
    echo medium
else
    echo high
fi
```

执行效果：

```bash
./classify.sh 49
```

输出：

```text
low
```

```bash
./classify.sh 50
```

输出：

```text
medium
```

```bash
./classify.sh 79
```

输出：

```text
medium
```

```bash
./classify.sh 80
```

输出：

```text
high
```

无效输入：

```bash
./classify.sh high
```

没有输出，退出状态为：

```text
2
```

同样：

```bash
./classify.sh 049
```

也不会产生输出，退出状态为：

```text
2
```

# 常见误区

## 误区 1：先赋值，再直接用算术判断验证输入

```bash
score=$1

if (( score < 50 )); then
    ...
fi
```

如果 `$1` 来自用户，这种写法并不能证明它是数字。

正确原则是：

```text
先验证文本格式 → 再进入算术环境
```

---

## 误区 2：只检查是不是全部由数字组成

```bash
[[ "$1" =~ ^[0-9]+$ ]]
```

这会接受：

```text
049
```

如果后续直接交给 Bash 算术运算，就可能触发八进制解释。

如果要求输入为规范的非负十进制整数，更合适的是：

```bash
[[ "$1" =~ ^(0|[1-9][0-9]*)$ ]]
```

---

## 误区 3：第二个分支重复写完整范围

可以写：

```bash
elif (( score >= 50 && score < 80 )); then
```

但没有必要。

因为进入 `elif` 时，程序已经知道：

```bash
score >= 50
```

所以只需要：

```bash
elif (( score < 80 )); then
```

---

## 误区 4：只测试普通值，不测试边界值

对于：

```text
< 50
< 80
```

最重要的测试数据包括：

```text
49
50
79
80
```

因为它们位于条件切换的位置。

此外还应该测试无效输入：

```text
high
049
```

这样才能同时检查：

* 数值范围；
* 边界条件；
* 输入校验；
* 退出状态。
