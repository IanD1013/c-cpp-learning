在许多编程语言中，变量可以被理解成一个**带标签的盒子**，盒子里面装着一个值。

但 Python 并不是这样工作的。尽早建立正确的理解，可以避免以后遇到很多令人困惑的问题。

在 Python 中：

> **变量（variable）是绑定到对象（object）上的名字（name）。**

对象存在于内存中的某个位置，而变量名只是一个指向该对象的标签。

赋值操作并不是把一个值复制到某个“盒子”里，而是：

> **让一个名字指向某个对象。**

理解这一点，就能解释 Python 中很多重要概念，例如：

- **别名（aliasing）**
- **重新绑定（rebinding）和修改对象（mutating）的区别**
- 为什么**可变对象（mutable objects）**和**不可变对象（immutable objects）**在赋值时表现得如此不同

### 一切都是对象

在 Python 中，每一个值都是**对象（object）**：

- 整数
- 字符串
- 列表
- 函数
- 类
- 甚至模块

全部都是对象。

一个对象始终具有三个东西：

1. **身份（identity）**：对象在内存中的身份，在对象生命周期内不会改变
2. **类型（type）**：这个对象是什么类型
3. **值（value）**：对象所表示的数据

```python
x = 42

print(type(x))      # <class 'int'>
print(type(print))  # <class 'builtin_function_or_method'>
```

`type(obj)` 可以告诉你对象所属的类。

`id(obj)` 会返回一个整数，在该对象存活期间，这个整数可以唯一标识这个对象。

如果两个名字对应的 `id()` 相同，那么它们指向的就是**完全相同的对象**。

```python
a = [1, 2, 3]

print(type(a))          # <class 'list'>
print(id(a) == id(a))   # True，同一个对象
```

### 赋值是绑定名字，而不是复制对象

下面这行代码：

```python
b = a
```

**不会复制 `a` 指向的对象。**

它只是让 `b` 成为指向同一个对象的另一个名字。

也就是说，`a` 和 `b` 是同一个对象的两个**别名（aliases）**。

```python
a = [1, 2, 3]
b = a

print(id(a) == id(b))  # True，一个对象，两个名字

b.append(4)

print(a)  # [1, 2, 3, 4] -- a 也能看到这个变化
```

这里只有**一个列表对象**。

可以想象成：

```text
a ─────┐
       ├──→ [1, 2, 3]
b ─────┘
```

`a` 和 `b` 都只是指向这个列表对象的标签。

因此：

```python
b.append(4)
```

修改的是它们共同指向的列表对象：

```text
a ─────┐
       ├──→ [1, 2, 3, 4]
b ─────┘
```

所以通过 `b` 对列表进行修改后，通过 `a` 也能看到这个变化。

如果你原本认为 `b = a` 会创建一个独立的副本，这种行为可能会让你感到意外。

### 重新绑定 vs 修改对象

这两个操作看起来很相似，但实际上完全不同。

**修改对象（mutating）**是修改对象本身。

对象的身份不会改变，任何指向这个对象的名字都可以看到这个变化。

**重新绑定（rebinding）**则是让一个名字改为指向另一个对象。

原来的对象完全没有被修改，其他仍然指向原对象的名字不会受到影响。

例如：

```python
a = [1, 2, 3]
b = a

b = [9, 9]      # 将 b 重新绑定到一个新的列表

print(a)        # [1, 2, 3]
print(b)        # [9, 9]
```

最开始：

```text
a ─────┐
       ├──→ [1, 2, 3]
b ─────┘
```

执行：

```python
b = [9, 9]
```

之后：

```text
a ───────→ [1, 2, 3]

b ───────→ [9, 9]
```

这里并没有修改原来的 `[1, 2, 3]`。

只是让 `b` 改为指向一个新的列表对象。

与之对比，下面是**修改对象（mutation）**：

```python
a = [1, 2, 3]
b = a

b.append(4)     # 修改共享的列表对象

print(a)        # [1, 2, 3, 4]
```

此时：

```text
a ─────┐
       ├──→ [1, 2, 3, 4]
b ─────┘
```

普通的：

```python
=
```

以及：

```python
b = ...
```

都会进行**重新绑定（rebinding）**。

而类似：

```python
b.append(...)
```

这样的列表方法，以及：

```python
b[0] = 9
```

这样的元素赋值，会**修改对象本身（mutate）**。

### 可变对象 vs 不可变对象

Python 中的一些对象可以被**原地修改（in place）**，它们叫作**可变对象（mutable objects）**。

常见的可变对象包括：

```python
list
dict
set
```

另一些对象创建之后就不能被原地修改，它们叫作**不可变对象（immutable objects）**。

常见的不可变对象包括：

```python
int
float
str
tuple
bool
frozenset
```

对于不可变对象来说，不存在“修改原对象”这件事情。

所以任何看起来像是在修改它的操作，实际上都是：

1. 创建一个新的对象
2. 将变量名重新绑定到这个新对象

例如：

```python
a = 5
b = a

b += 1          # int 不可变：创建新的 6，然后将 b 重新绑定到 6

print(a, b)     # 5 6 -- a 没有变化
```

最开始：

```text
a ─────┐
       ├──→ 5
b ─────┘
```

执行：

```python
b += 1
```

之后：

```text
a ───────→ 5

b ───────→ 6
```

原来的整数对象 `5` 并没有被修改成 `6`。

Python 创建了新的整数对象 `6`，然后让 `b` 指向它。

字符串也是一样：

```python
s = "hi"
t = s

t += "!"        # str 不可变：创建 "hi!"，然后重新绑定 t

print(s, t)     # hi hi!
```

最开始：

```text
s ─────┐
       ├──→ "hi"
t ─────┘
```

之后：

```text
s ───────→ "hi"

t ───────→ "hi!"
```

因为不可变对象不会在你不知道的情况下发生变化，所以共享不可变对象通常是安全的。

真正容易因为**别名（aliasing）**产生问题的是可变对象。

如果两个名字指向同一个列表，那么通过其中任何一个名字修改这个列表，另一个名字都会看到变化。

### `None` 是一个特定的对象

`None` 是 `NoneType` 类型的唯一值。

它通常用来表示：

> **这里没有值。**

如果一个函数没有显式写 `return`，那么它默认返回 `None`。

```python
def f():
    pass

print(f())         # None
print(type(None))  # <class 'NoneType'>
```

在一个正在运行的 Python 程序中，只有一个 `None` 对象。

所有被赋值为 `None` 的名字都指向同一个 `None` 对象。

例如：

```python
a = None
b = None
```

可以理解成：

```text
a ─────┐
       ├──→ None
b ─────┘
```

因此，`None` 非常适合作为一个明确的：

> **“目前还没有值”**

的标记。
