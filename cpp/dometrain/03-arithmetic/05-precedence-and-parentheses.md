# C++ 运算符优先级、结合顺序与括号

在 C++ 中，一个表达式里同时出现多个运算符时，程序需要知道：

1. **哪个运算先做**
2. **同一级别的运算从哪边开始做**

这分别对应两个重要概念：

* **运算符优先级（precedence）**
* **结合性（associativity）**

---

## 1. 同一级运算符通常从左到右计算

例如：

```cpp
100 / 5 * 2
```

`/` 和 `*` 的优先级相同。

因此按照它们的结合顺序，从左向右理解：

```cpp
100 / 5 * 2
```

等价于：

```cpp
(100 / 5) * 2
```

先计算：

```cpp
100 / 5
```

得到：

```cpp
20
```

然后：

```cpp
20 * 2
```

得到：

```cpp
40
```

所以：

```cpp
100 / 5 * 2   // 40
```

而不是：

```cpp
100 / (5 * 2) // 10
```

---

## 2. 减法也是从左到右

例如：

```cpp
20 - 8 - 5
```

由于两个 `-` 的优先级相同，因此从左向右：

```cpp
(20 - 8) - 5
```

先算：

```cpp
20 - 8
```

得到：

```cpp
12
```

再算：

```cpp
12 - 5
```

得到：

```cpp
7
```

所以：

```cpp
20 - 8 - 5   // 7
```

它并不等于：

```cpp
20 - (8 - 5)
```

因为后者是：

```cpp
20 - 3
```

结果为：

```cpp
17
```

这说明：

> 对于减法和除法，改变分组方式通常会改变结果。

---

# 3. 运算符优先级

当不同类型的运算符同时出现时，C++ 会根据**优先级**决定先计算哪一个。

目前最重要的一组优先级可以记成：

```text
高优先级：
*   /   %

低优先级：
+   -
```

也就是说：

```cpp
* / %
```

会比：

```cpp
+ -
```

先执行。

例如：

```cpp
10 + 5 * 3
```

不是从最左边开始直接算。

因为 `*` 的优先级比 `+` 高，所以相当于：

```cpp
10 + (5 * 3)
```

先算：

```cpp
5 * 3
```

得到：

```cpp
15
```

再算：

```cpp
10 + 15
```

最终得到：

```cpp
25
```

所以：

```cpp
10 + 5 * 3   // 25
```

---

# 4. 括号可以改变默认运算顺序

如果希望加法先发生，可以使用括号：

```cpp
(10 + 5) * 3
```

括号中的表达式先作为一个整体进行计算：

```cpp
10 + 5
```

得到：

```cpp
15
```

然后：

```cpp
15 * 3
```

得到：

```cpp
45
```

因此：

```cpp
(10 + 5) * 3   // 45
```

和：

```cpp
10 + 5 * 3     // 25
```

结果完全不同。

---

# 5. 括号的真正作用

一个很重要的理解是：

> 括号不会改变某个运算符本身的行为，它只会改变表达式如何被分组。

例如：

```cpp
(first + second) * factor
```

这里的括号表示：

```cpp
first + second
```

应该先被看成一个整体。

假设：

```cpp
first = 10;
second = 5;
factor = 3;
```

那么：

```cpp
(first + second) * factor
```

相当于：

```cpp
15 * 3
```

结果是：

```cpp
45
```

而：

```cpp
first + second * factor
```

根据运算符优先级，会被理解成：

```cpp
first + (second * factor)
```

也就是：

```cpp
10 + 15
```

结果为：

```cpp
25
```

---

# 6. 括号有时不会改变结果

有时候加入括号只是把 C++ 原本就会采用的顺序明确写出来。

例如：

```cpp
10 + 5 * 3
```

默认就是：

```cpp
10 + (5 * 3)
```

所以写成：

```cpp
10 + (5 * 3)
```

结果没有变化。

这种括号虽然不是必须的，但在复杂表达式里可以提升可读性。

例如：

```cpp
total + (price * quantity) - discount
```

即使这里的括号按照优先级来说可以省略：

```cpp
total + price * quantity - discount
```

前一种通常更容易一眼看懂。

---

# 7. 优先级和结合性不是一回事

这两个概念容易混淆。

## 优先级

回答：

> 不同种类的运算符中，谁先分组？

例如：

```cpp
10 + 5 * 3
```

因为 `*` 的优先级更高：

```cpp
10 + (5 * 3)
```

---

## 结合性

回答：

> 如果运算符优先级相同，如何分组？

例如：

```cpp
100 / 5 * 2
```

`/` 和 `*` 优先级相同，因此按照从左到右：

```cpp
(100 / 5) * 2
```

再例如：

```cpp
20 - 8 - 5
```

两个 `-` 优先级相同，因此：

```cpp
(20 - 8) - 5
```

---

# 8. 当前阶段最值得记住的规则

对于基础算术表达式，可以先记住：

```text
括号
  ↓
* / %
  ↓
+ -
```

对于同一优先级的这些算术运算符，则通常从左向右分组。

例如：

```cpp
2 + 3 * 4
```

理解为：

```cpp
2 + (3 * 4)
```

结果：

```cpp
14
```

---

例如：

```cpp
20 / 5 * 2
```

理解为：

```cpp
(20 / 5) * 2
```

结果：

```cpp
8
```

---

例如：

```cpp
20 - 5 + 3
```

`-` 和 `+` 同一级，因此从左向右：

```cpp
(20 - 5) + 3
```

结果：

```cpp
18
```

---

# 9. 一个常见误区：不要简单理解为“永远从左到右算”

例如：

```cpp
10 + 5 * 3
```

如果机械地从左往右计算：

```cpp
10 + 5 = 15
15 * 3 = 45
```

这是错误的。

正确顺序由优先级决定：

```cpp
10 + (5 * 3)
```

结果：

```cpp
25
```

因此更准确的理解是：

> 先根据运算符优先级进行分组；如果运算符处于同一优先级，再根据结合性决定分组方向。

---

# 10. 用括号直接表达程序意图

实际写代码时，不需要故意依赖复杂的优先级规则。

如果一个表达式表达的是：

> first 和 second 先相加，然后结果乘 factor

那么最好直接写：

```cpp
(first + second) * factor
```

而不是试图依赖读者自己理解你的意图。

同理，如果要：

> first 和 second 相加
> → 乘以 factor
> → 最后减去 offset

数学结构就是：

```text
((first + second) × factor) - offset
```

对应 C++：

```cpp
(first + second) * factor - offset
```

因为 `*` 本身比 `-` 优先，所以最外面的乘积不需要额外括号。

当然，也可以写成：

```cpp
((first + second) * factor) - offset
```

含义完全相同。

---

# 总结

最重要的几点：

```cpp
100 / 5 * 2
```

相当于：

```cpp
(100 / 5) * 2
```

因为 `/` 和 `*` 同一级，并且从左向右分组。

---

```cpp
20 - 8 - 5
```

相当于：

```cpp
(20 - 8) - 5
```

---

```cpp
10 + 5 * 3
```

相当于：

```cpp
10 + (5 * 3)
```

因为 `*` 的优先级比 `+` 高。

---

```cpp
(10 + 5) * 3
```

括号改变了默认分组，因此结果从 `25` 变成 `45`。

可以把当前需要掌握的规则总结为：

```text
先看括号
再看 * / %
最后看 + -

同一级算术运算通常从左向右分组
```
