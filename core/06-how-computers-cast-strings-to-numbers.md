# 计算机是怎么把字符串转成数字的

> 视频来源：Core Dumped -《HOW COMPUTERS CAST STRINGS TO NUMBERS》
> https://www.youtube.com/watch?v=m8v_SRpxyN4

## 0. 这一期在讲什么

几乎所有主流语言都自带一个把字符串转成数字的工具：

| 语言 | 工具 | 出处 |
| --- | --- | --- |
| C | `atoi()` | 标准库 |
| Python | `int()` | 语言内置函数 |

问题是：**如果你的语言没有提供这个工具，你自己写得出来吗？**

这一期就是把这个黑盒拆开，从「计算机为什么只认数字」一路推到能自己实现的算法。

---

## 1. 前置：计算机只会处理数字

计算机只能处理和记住 1 和 0，换句话说，**它只会处理数字**。

它不理解什么是字符，也不理解什么是颜色。
所以当我们需要它记住这类非数值信息时，唯一的办法是：**把这些数据编码（encode）成数字**。

最典型的例子是 **ASCII 表**：把每一个可能出现的字符和一个特定的二进制数关联起来，存的是那个数。

比如要记住单词 `hello`，内存里存的不是「字符」，而是五个数：

```text
    'h'      'e'      'l'      'l'      'o'
     104      101      108      108      111
  ┌────────┬────────┬────────┬────────┬────────┐
  │01101000│01100101│01101100│01101100│01101111│
  └────────┴────────┴────────┴────────┴────────┘
   byte0    byte1    byte2    byte3    byte4
```

本期为了简单只用 ASCII。
但要记住，现代计算机用的是 **Unicode**，它是 ASCII 的**超集（superset）**。
作者说 Unicode 会另开一期讲，超出本期范围。

## 2. 问题的源头：键盘给你的永远是文本

用户按下键盘时发生了什么？

最容易理解的模型是：**每按下一个键，对应字符的 ASCII 码就被存进一个缓冲区（buffer）。**

我们写的程序在需要用户输入时，拿到的一般就是这个缓冲区里的内容。

```text
  用户敲下  5   和   3
              │
              ▼
   ┌──────────────────────┐
   │ buffer:  '5'    '3'  │
   │        00110101 00110011 │
   │          53      51  │
   └──────────────────────┘
              │
              ▼
        你的程序拿到的是这个
```

这意味着：

> **即使用户输入的是数字，你的程序收到的也只是「装着数字字符的一段纯文本」。**

很多人的困惑就是从这里开始的。

### 2.1 直接相加会得到什么

考虑一个最简单的程序：让用户输入两个数，输出它们的和。

因为这两个数是以**字符**形式提供的，我们**不能直接把缓冲区里的比特加起来**，它们根本不是我们想加的那两个数。

别误会，缓冲区里存的确实是 1 和 0，计算机**确实能**把它们加起来。
只不过那些比特代表的是**字符 `5` 和字符 `3`**，不是**数字 5 和数字 3**：

```text
        想要的                     实际发生的
   ─────────────────         ────────────────────────
        5                     '5' 的编码 = 53
      + 3                   + '3' 的编码 = 51
   ─────────────────         ────────────────────────
        8   ✔                        104   ✘
```

结果是 104，错得离谱。

所以：

> **把这段字符信息转换成用户想表达的那个数字，是我们自己的活。**

### 2.2 多位数让事情更复杂

有人会想：那我把每个字符各自转成它代表的数不就行了？

不行。
**把每一位转好之后，这些比特在内存里并排放着，并不代表你想要的那个数。**

```text
字符串 "43"
   '4' -> 4 -> 00000100
   '3' -> 3 -> 00000011

并排放在内存里
┌────────┬────────┐
│00000100│00000011│   = 0000010000000011 = 1027
└────────┴────────┘
                       但我们要的是 43
```

所以必然存在一个**过程**，才能把字符串正确地转成数字。
下面就是这个过程。

---

## 3. 第一步：单个数字字符怎么转

### 3.1 ASCII 表里数字字符是「连在一起且有序」的

打开 ASCII 表会发现一件事：**10 个数字字符不但被分在一组，而且是按顺序排列的。**

这不是巧合，这个设计有多个原因，本期只关心和我们问题相关的那一个。

第一个数字字符 `0` 的编码是：

```text
   '0'  =  00110000  =  48
   '1'  =  00110001  =  49
   '2'  =  00110010  =  50
   '3'  =  00110011  =  51
   ...
   '9'  =  00111001  =  57
        └────┬────┘
       高 4 位固定是 0011
             低 4 位正好就是它代表的数字
```

既然数字字符是**连续且有序**的，我们可以这样理解这套编码：

> **每个数字字符的编码 = 它真正代表的数字 + 48。**

于是反过来：

> **把任何一个数字字符转成它代表的数字，只要用它的编码减去 48。**

```text
   '7' 的编码 55
   - 48
   ─────
      7   ← 这就是它代表的数字
```

### 3.2 在语言里怎么写

先澄清一件事：**在 C 这样的低级语言里，把字符用在数值运算中，实际上就是让计算机拿「编码这个字符的那个数」当操作数。**

```c
'2' - 48        /* 实际是 50 - 48 = 2 */
```

`'2'` 的编码是 50，`50 - 48 = 2`，我们就拿到了这个字符代表的数字。
这和上面从 ASCII 表推出来的结论完全一致。

不同语言需要的步骤不一样：

| 语言 | 写法 | 说明 |
| --- | --- | --- |
| C | `c - 48` | 字符本身就能直接参与数值运算 |
| Python | `ord(c) - 48` | 需要 `ord()` 先取出编码这个字符的数 |

### 3.3 不要硬编码 48

**因为我们是好程序员，不该把 48 写死。**

更好的写法是：用「编码第一个数字字符 `0` 的那个数」来代替它。

```c
c - '0'          /* C：'0' 会被当成它的编码 48 */
```

```python
ord(c) - ord('0')    # Python
```

意思完全一样，但意图更清楚，也不依赖你记住 48 这个数。

## 4. 第二步：多位数怎么拼起来

### 4.1 先回忆十进制是什么意思

我们写下一个十进制数 `4327` 的时候，表达的其实是一个数量：

```text
  4   3   2   7
  │   │   │   └── 7 个   一      =  7 × 10⁰ =     7
  │   │   └────── 2 个   十      =  2 × 10¹ =    20
  │   └────────── 3 个   百      =  3 × 10² =   300
  └────────────── 4 个   千      =  4 × 10³ =  4000
                                   ───────────────────
                                   合计        =  4327
```

只要我们已经会把每个字符转成它代表的数字，计算机就能照着同一套流程走：

* 最右边那位乘 `10⁰`（也就是 1）；
* 往左一位乘 `10¹`；
* 再往左乘 `10²`；
* 再往左乘 `10³`；
* 最后全部加起来。

**转换每一位是整个流程的一部分，所以我们其实已经走完一半了。**

### 4.2 一个麻烦：不能先去数长度

按 4.1 的思路，得先知道每一位该乘 10 的几次方，也就是得先知道**字符串有多长**。

直觉上，取个长度不就行了？

作者在这里给了一个很实际的理由说明为什么不这么做：

> **取字符串长度在不同语言里的时间复杂度不一样。**
>
> 有些语言里字符串是对象或结构体（长度是现成的字段），
> 有些语言里字符串就是一个字符数组（得自己走一遍才知道多长）。

我们不想在这里操心这些差异，所以换一条路。

### 4.3 换个思路：让累加变量自己记住位数

做法是：**每读到一位，先把已经累积的结果乘以 10，再把这一位加上去。**

乘以 10 的效果是「把整个数往左移一位」，这样新读到的数字自然落在个位上。

关键在于，这个乘法是**反复施加**的：

```text
读到第 3 位时，做一次 ×10：
   ├── 上一位（第 2 位）被乘了 1 次 10   ->  升到十位
   └── 上上位（第 1 位）已经被乘过 1 次，这次是第 2 次  ->  升到百位
```

也就是说，**每个数字会被自动乘上恰好它需要的那么多次 10**。

> 这就是为什么我们根本不需要知道字符串的长度。

### 4.4 手动跑一遍 "4327"

字符串是一个字符数组，我们从左往右遍历，用一个变量 `result` 累加结果。

下面同时给出十进制和二进制，但记住：**二进制那一列才是计算机里真正发生的事。**

**初始状态**

```text
result = 0        00000000 00000000
```

**第 1 轮：字符 '4'**

```text
   '4' 编码 52  ->  52 - 48 = 4

   此时我们还不知道后面还有几位，
   所以先不管乘法，直接记住它，留给后面的迭代用。

   result = 0 × 10 + 4 = 4
   result = 4       00000000 00000100
```

**第 2 轮：字符 '3'**

```text
   '3' 编码 51  ->  51 - 48 = 3

   不能直接 4 + 3。
   因为 '4' 在 '3' 左边一位，它应该比 3 高一个数量级。
   所以先把 result 乘 10，把 4 左移一位变成 40：

   result = 4 × 10 + 3 = 43
   result = 43      00000000 00101011
```

**第 3 轮：字符 '2'**

```text
   '2' 编码 50  ->  50 - 48 = 2

   result = 43 × 10 + 2 = 432
   result = 432     00000001 10110000

   注意这一次的 ×10 同时做了两件事：
   ├── 把上一位的 3 从个位抬到十位
   └── 把上上位的 4 从十位再抬到百位（它已经是第 2 次被乘 10 了）
```

**第 4 轮：字符 '7'**

```text
   '7' 编码 55  ->  55 - 48 = 7

   result = 432 × 10 + 7 = 4327
   result = 4327    00010000 11100111
```

**字符串没有字符了，`result` 里的值就是我们要找的那个数。**

在这个例子里，这个数在内存中占 **2 个字节**：

```text
      byte1      byte0
   ┌──────────┬──────────┐
   │ 00010000 │ 11100111 │  = 4327
   └──────────┴──────────┘
```

整个流程画成一条线是这样：

```text
  "4327"
    │
    ├─ '4' ─► 4 ─►  result = 0×10 + 4    =    4
    ├─ '3' ─► 3 ─►  result = 4×10 + 3    =   43
    ├─ '2' ─► 2 ─►  result = 43×10 + 2   =  432
    └─ '7' ─► 7 ─►  result = 432×10 + 7  = 4327
                                             │
                                             ▼
                                          返回 4327
```

动画看起来一步到位，但**计算机不是一次算完的，它是一步一步顺序执行的**。

## 5. 代码

两种语言里的同一个函数，做的就是我们刚学的这件事：

**接收一个字符串 -> 用一个变量累加结果 -> 遍历每个字符 -> 算出它代表的数字，加到「之前累积值的 10 倍」上 -> 没有数字了就返回累加变量。**

### C

```c
int str_to_int(const char *str) {
    int result = 0;
    for (int i = 0; str[i] != '\0'; i++) {
        result = result * 10 + (str[i] - '0');
    }
    return result;
}
```

### Python

```python
def str_to_int(s):
    result = 0
    for ch in s:
        result = result * 10 + (ord(ch) - ord('0'))
    return result
```

### 5.1 让它更健壮

现在的版本假设字符串里全是数字字符。
要更健壮，应该**检查每个字符是不是数字字符，不是就返回某种错误**。

```c
int str_to_int(const char *str) {
    int result = 0;
    for (int i = 0; str[i] != '\0'; i++) {
        if (str[i] < '0' || str[i] > '9') {
            return -1;          /* C 里没有真正的错误机制，习惯用 -1 表示出错 */
        }
        result = result * 10 + (str[i] - '0');
    }
    return result;
}
```

作者的原话是：**在 C 里我们通常返回 -1，因为 C 本身并不存在「错误」这种东西。**

## 6. 反过来的那一半：打印

最后留一个思考。

我们用计算机做完计算，通常要把结果**打印出来**。
但内存里存的结果是一个二进制数，人类很难直接看懂，所以我们把它**打印成格式化为字符串的十进制数**。

做法是把这个数交给 print 函数，它会自动格式化成字符串。

```text
   输入方向（本期学的）
   "4327"  ──► 逐位 -'0'，逐轮 ×10+digit ──►  4327

   输出方向（print 内部做的）
    4327   ──►  ??? ──►  '4' '3' '2' '7'
                          需要求出每一位字符的 ASCII 码
```

也就是说，print 内部必然有一个过程，去求出「这个数用十进制表示时，每一位字符对应的 ASCII 码」。

> **这正好是本期学的过程的反过程。**

作者说，想看这一部分可以在评论区留言，属于未来某一期的内容，超出本期范围。

## 7. 核心总结

```text
字符串怎么变成数字
│
├── 为什么需要转换
│   ├── 计算机只会处理数字，字符必须被编码（ASCII / Unicode）
│   ├── 键盘输入进的是 buffer 里的 ASCII 码，程序拿到的永远是文本
│   ├── 直接相加 '5' + '3' = 53 + 51 = 104，不是 8
│   └── 每位各转各的也不行：00000100|00000011 = 1027，不是 43
│
├── 单个字符：靠 ASCII 表的设计
│   ├── 10 个数字字符在表里连续且有序，'0' = 48
│   ├── 编码 = 它代表的数字 + 48  ->  减 48 即可还原
│   ├── C 里字符可直接参与运算，Python 要先 ord()
│   └── 别写死 48，写 '0' / ord('0')
│
├── 多位数：不需要知道字符串长度
│   ├── 十进制的含义 = Σ 每位 × 10^位置
│   ├── 取长度在不同语言里复杂度不同，所以绕开它
│   └── result = result × 10 + digit
│       └── ×10 会把之前所有位一起左移
│           ==> 每一位自动被乘上恰好需要的次数
│
├── 实现
│   ├── 一个累加变量 + 一次遍历，C 和 Python 完全同构
│   └── 健壮版：非数字字符就报错（C 惯例返回 -1）
│
└── 还有反过来的一半
    └── print 把数字转回十进制字符串，是本期的逆过程（未来话题）
```

> 计算机看不到「数字」，它只看到一串被编码成数的字符。
> 把它们变回数字只需要两件事：**减去 `'0'` 把字符还原成数位**，
> 以及 **`result = result × 10 + digit`**，让每一位在累加的过程中自动升到它该在的数量级。
> 这就是 `atoi()` 和 `int()` 在黑盒里做的全部事情。
